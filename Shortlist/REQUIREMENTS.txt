1. PROJECT OVERVIEW
================================================================================

Product Name  : Uhired (AI Interview Platform)
Stack         : Next.js 16 (App Router) · TypeScript · Prisma · PostgreSQL
                Tailwind CSS 4 · OpenAI · Razorpay · SMTP · S3/Supabase Storage

Primary Goal  :
  - Restructure the project into a clean, scalable structure
  - Add an attractive marketing frontend (Home, About, Contact Us)
  - Make the backend secure and maintainable with proper API-key handling
  - Do NOT create extra models, dialogs, or duplicate code

Success Looks Like :
  - A professional marketing Home page at "/"
  - "/about" and "/contact" pages live
  - Practice flow on a separate route (e.g. "/practice") — linked from the Home CTA

7. FEATURE REQUIREMENTS — BACKEND & API KEYS
================================================================================

7.1 ENV VALIDATION MODULE (src/lib/env.ts)
------------------------------------------
  Must Have:
    - Zod schema for all required env vars
    - server-only import
    - Fail fast on missing OPENAI_API_KEY, DATABASE_URL in production
    - Separate: server secrets vs NEXT_PUBLIC_* (only Razorpay public key)
    - Typed export: env.OPENAI_API_KEY, env.DATABASE_URL, etc.
    - Dev mode: warn on missing optional keys, don't crash

7.2 INTEGRATION CLIENT PATTERN
-------------------------------
  Each external service = one module in src/lib/integrations/<provider>/

  OpenAI:
    - All fetch calls go through integration client
    - Timeout: 30s default
    - Error: typed IntegrationError (message safe for logs, no key leak)
    - Used by: /api/ai/*, /api/interview/*/realtime, scoring

  Razorpay:
    - Server: RAZORPAY_KEY_SECRET only in integrations/razorpay/
    - Client: NEXT_PUBLIC_RAZORPAY_KEY_ID unchanged
    - Used by: /api/practice/payment/*

  SMTP (Email):
    - SMTP_PASS server-only
    - Used by: invite emails, contact form (if email mode chosen)
    - Existing SMTP_SEND_DELAY_MS, SMTP_MAX_RETRIES respected

  Storage (S3 / Supabase):
    - AWS_SECRET_ACCESS_KEY, SUPABASE_SERVICE_ROLE_KEY server-only
    - No change to storage logic — only move files to integrations/storage/

7.3 CONTACT API (POST /api/contact)
------------------------------------
  Request body:
    { name: string, email: string, subject: string, message: string, honeypot?: string }

  Behavior:
    - Zod validate input
    - Reject if honeypot filled (return 200 silently or 400 — pick one, document it)
    - Rate limit: max 5 requests per IP per hour (in-memory OK for v1)
    - Delivery mode (CHOOSE ONE for v1):
        Option A (Recommended): Send email via existing SMTP to admin inbox
        Option B: Save to ContactMessage table in DB
        Option C: Both — ONLY if explicitly needed (avoid duplicate notifications)

  Response:
    { ok: true } on success
    { error: "message" } on failure (no internal stack traces)

  Must NOT:
    - Store API keys in request/response
    - Create admin UI for contact messages in v1

7.4 EXISTING API ROUTES — NO BREAKING CHANGES
----------------------------------------------
  All existing endpoints keep same URLs and behavior.
  Only internal refactor: process.env → env.* from validated module.
